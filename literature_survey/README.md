# Literature Survey

Fifteen papers reviewed for the project (twelve from indexed venues, three recent arXiv preprints). The same tables appear in
Section 2 of the project report ([docs/Project_Report.docx](../docs/Project_Report.docx)); full APA references are in
[references/README.md](../references/README.md).

**Changes from the proposal:** the proposal's paper on machine learning and cloud-based knowledge graphs for recognising suicidal
tendencies has been retracted by its publisher, and the paper "Automated Knowledge Graph Construction for Intelligent Research
Information Systems" could not be found in Crossref or any index. They were replaced by P4 (Pan et al., IEEE TKDE 2024) and
P9 (Peng et al., ACM TOIS 2025).

## Individual research gap analysis

Each member analysed five papers related to their area: Devesh Agarwal (data and NLP extraction), Dhruv Gupta (knowledge graph
and GraphRAG), Parth Sharma (cloud deployment and application).

| Paper | Analyst | Existing method | Advantages | Limitations | Research gap identified | Possible improvement |
|---|---|---|---|---|---|---|
| P2 | Devesh | Deep-learning pipelines for extraction, fusion and reasoning | End-to-end learning from unstructured text | Treated as a review: no deployed system, cost or latency figures | Construction methods are rarely evaluated as a running service with throughput and failure rates | Serve the extraction model behind an event-driven pipeline and report documents/hour and failures (done: Section 10) |
| P5 | Devesh | LLM/spaCy extraction plus clustering and link prediction | Connects fragmented subgraphs; human-readable clusters | General-purpose extractors are noisy on scientific terms; embedding models need retraining for new entities | Domain-specific entity types (Method, Task, Dataset, Metric) need a model trained on scientific text | Fine-tune SciBERT on SciERC and canonicalise names before writing the graph |
| P8 | Devesh | Library interfaces, NLP screening and a KG of SLR results | Automates acquisition and screening | Depends on publisher web interfaces; no full-text reading or natural-language querying | The resulting graph is browsed, not asked; publisher scraping is fragile | Use open APIs (OpenAlex, S2ORC) instead of scraping and add GraphRAG question answering |
| P11 | Devesh | Survey of extraction, learning and evaluation | Broad, recent overview across domains | Notes that LLM extraction hallucinates triples without post-processing | Need for measurable extraction quality and graph-level effects, not only model scores | Report entity- and relation-level F1 on a public test set and the before/after effect on the graph |
| P14 | Devesh | Ontology-driven KG with concepts linked to Wikipedia | Large unified KG; good linking accuracy for common concepts | Niche concepts missing from Wikipedia link poorly; relies on explicit text | Scientific methods and datasets are often too new or niche for encyclopaedia linking | Canonicalise with learned abbreviations and alias tables, and enrich papers from OpenAlex metadata |
| P3 | Dhruv | Zero-shot LLM triplet extraction and two-stage KG-RAG | High accuracy without fine-tuning the LLM | Accuracy depends on KG coverage; single domain; self-built test set | No measurement of the same LLM with and without the graph on the same questions | Run a controlled benchmark: same model, same questions, with and without graph context (done: 0% vs 62.5% hallucination) |
| P4 | Dhruv | Roadmap for unifying LLMs and KGs | Clear taxonomy of integration patterns | Conceptual; few deployable reference systems | Few end-to-end systems show KG-grounded LLM answers with citations at low cost | Build a deployed, cited GraphRAG system on serverless cloud services |
| P9 | Dhruv | Survey of GraphRAG indexing, retrieval and generation | Systematic view of the design space | Limited guidance on latency and cost of graph retrieval | Multi-hop retrieval latency inside API time limits is rarely reported | Run graph queries in parallel and time-box the LLM (measured 0.535 s retrieval; 30 s API limit never exceeded) |
| P12 | Dhruv | LLM-guided context filtering for KG completion | Removes redundant paths before scoring | Simple path context only; less stable in inductive settings | Retrieved context must be ranked by relevance to the question, not only filtered | Score facts by match quality, relation type and question wording before passing the top 30 to the LLM |
| P13 | Dhruv | Multi-agent RAG over per-subject KGs | Prevents cross-domain interference | Small human evaluation; weights not calibrated | Grounded generation needs an objective, automatic evaluation | Generate questions with ground truth from the graph and score recall, hallucination and citation precision automatically |
| P1 | Parth | Human-centric KG with ontologies and semantic queries | Captures multi-hop operational relations | Manual ontology engineering; structured inputs only | No automated pipeline from unstructured text to the graph | Event-driven ingestion: S3 upload triggers Lambda, SageMaker extraction and graph writes |
| P6 | Parth | Decentralised knowledge sharing with GraphSAGE | No central bottleneck | Evaluated in simulation only | Cloud deployment, security and monitoring of KG services are not addressed | Deploy as managed serverless services with Cognito, IAM least privilege and CloudWatch monitoring |
| P7 | Parth | Survey of KG technologies and applications | Comprehensive; identifies multi-hop cost | Survey only | Practical bounds on multi-hop cost in an interactive application are missing | Limit expansion to 3 hops and 27 bounded parallel queries; measure latency |
| P10 | Parth | Hierarchical few-shot KG completion | Handles long-tail relations | High model complexity; no deployment discussion | Heavy models are costly to serve; inference cost matters for cloud systems | Serve compact BERT-size models on a serverless endpoint that costs nothing when idle |
| P15 | Parth | Diffusion model for unseen entities | Works without auxiliary information | Slower inference due to diffusion | Graphs of literature grow continuously; new entities must appear without retraining | Add new papers incrementally with idempotent MERGE writes so new entities are queryable immediately |

## Consolidated research gap

No reviewed system combines automatic extraction of scientific entities and typed relations from literature, a continuously
updated graph, question answering that cites its sources and is measured against the same LLM without the graph, and a secure,
monitored, low-cost cloud deployment. This project addresses that combined gap.
